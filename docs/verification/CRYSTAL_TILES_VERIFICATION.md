## 素材與整合

- `assets/tiles-crystal/` 使用四張 `-no-label.png` 與原字牌／牌背 PNG。前四者由內建 `image_gen` 編輯，去掉圖中原有小字；字牌圖集未變。選用檔案與來源副本逐位元組一致，來源及 SHA-256 記於 runtime manifest。萬／筒／條圖集維持 1086×1448；字牌牌背／八花圖集維持 1536×1024。
- `crystal-tiles.js` 保存 43 個獨立且互不重疊的來源矩形，利用 SVG 視窗顯示原始像素。每張來源牌寬至少 292 像素、高至少 439 像素。未以放大重採樣充當高解析度。
- 只有東、南、西、北、中、發保留清楚的 SVG 字標；27 種數牌、八花、白板與牌背不加字。牌名仍可由遊戲原本的無障礙標籤／提示辨識，圖鑑的圖外說明保留。花牌保留 `data-flower`，遊戲特效要求的 `<svg class="tile-art"` 前綴未變。
- 初次整合在 `index.html` 增加兩個資源載入與 `tileFace` 的新模組入口，原 SVG 備援仍在；後續另調整結算頁的顯示標記。牌型、計分、AI、存讀檔與牌局流程未改。
- `crystal-tiles.css` 同時處理手牌、棄牌、副露、結算、動畫與對家牌背。對家牌背旋轉 180°，左右家使用相反的 90° 旋轉。
- 自家副露與手牌依實際總張數共同調整牌寬，整排同時可見，沒有水平捲動。所有模式都限制於桌內兩側各 8px、底部 30px 的牌架；不再借用 play-column 的桌外寬度。手機下方控制區預留由 144px 減為 80px，桌框與桌面仍為正方形，位置與尺寸隨可用空間重算。

## 實際顯示大小與結算頁改善

使用者回報一般螢幕上的牌圖仍模糊，並要求結算頁牌張不換行、文字清楚。DPR 1 比對顯示，來源像素足夠並不等於小尺寸細節容易辨識；扁平化 SVG、強制銳利縮放與像素對齊未帶來值得採用的改善，因此保留 PNG 與渲染方式，調整顯示空間。

- `crystal-tiles.css` 移除牌圖外重複的 CSS 邊框。`table-layout.js` 的 `fitPersonalRack()` 按桌內寬度、手牌／副露實際張數、組間距與摸牌間隔計算共同牌寬，手牌間距為 1px。副露維持手牌的 0.86 比例，所有牌同排；捲動箭頭已移除。一般模式牌寬上限 50px，緊湊模式上限 40px，保留 5:7 比例。
- 本輪所有模式的牌架都回到桌內，左右各留 8px、距底部 30px。手機下方控制區預留降為 80px、狀態訊息位於桌下 67px；方桌位置與尺寸依可用空間重算。`fitBottomDiscards()` 以實際棄牌 `.tile` 數量，在中央資訊下方或兩側棄牌下方選擇可用空間，避免壓住手牌；每次先清除舊定位樣式，無可用高度時回到預設版面。緊湊模式的自家棄牌區另設 `min-height: 0`，移除會攔住懸停手牌的多餘空白。
- 上一輪 `lounge.css` 與 `index.html` 的 `showHandsAndContinue()` 使用依張數配置的等寬格，副露再依組內牌數分配寬度；結算的手牌、花牌與副露各自整排直接可見，不必水平捲動。當輪結算 17 張手牌在 943／1440px 視窗每張 50px，在 320／390px 視窗約 17.28／21.41px。內文、頁首小字與區段標籤至少 14px、玩家名稱 16px、分數 18px、主標題 24px，使用系統無襯線字型。下一局按鈕隨內容排列，避免遮住最後一家的牌；本輪未改此結算版面，也未重跑結算測試。
- 桌內同排放 17 張受實際寬高限制。本輪完整手牌測得 320×568 為 14px、390×844 為 18px、844×390 為 13px、943×889 為 40px、1440×1000 為 49px；多槓副露還會再縮小。不能宣稱小螢幕具有 50px 牌面的細節與點選空間，橫放也不保證變大。保持原高解析晶石 PNG 與無角標設定，未以隱藏、重疊、截斷或強制捲動充當全排可見。
- 上一輪結算顯示前後玩家牌資料與分數一致；含引號與 HTML 字元的玩家名稱已於前次唯讀檢查確認安全顯示，逸出邏輯未變。當輪 943px 實際點下一局後進入 `deal`、結算視窗關閉；完整開局生命週期另由本輪 `opening-browser` 重跑驗證。
- 本次未重製或銳化圖片，保留數牌／花牌無角標、字牌可留字的設定。
