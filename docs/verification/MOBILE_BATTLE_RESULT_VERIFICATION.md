# 手機戰鬥與結算介面驗證

日期：2026-10-25。

## 重現與修正

- 手機展開戰況仍套用舊兩欄排版，但面板只有320px，且內容超高時使用`overflow:hidden`。改為單欄上下捲動，日誌和狀態可換行；傷害與仇恨欄依數字寬度配置。
- 568×320中央怪物資訊碰到上方牌列，縮減極短橫式畫面的列間距。
- 多個吃、碰、槓、胡選項同時出現時，操作列會蓋到怪物攻擊資訊。手機按鈕統一44px；700px以下橫式在有可用操作時，暫時將怪物資訊改為橫向排列並上移，回應後恢復原排列。保留生命、技能、攻擊、目標及出手倒數。
- 結算改變視窗尺寸時，`showResult`重寫標題區，連帶移除修為與巡歷明細。保留原結算節點及其非同步處理，不重新發放獎勵。

## 驗證方式

`node tests/battle-result-layout-browser.cjs`使用獨立瀏覽器與本機HTTP服務，覆蓋Chromium／WebKit、568×320、667×375、844×390、942×435及1440×900。

- 實際開始修仙旅程，檢查手牌命中點、怪物內容與牌列邊界、角色名稱、戰況捲動，以及角色／怪物詳情開關。
- 明示的顯示fixture：五個回應按鈕同時出現，傷害1,234,567、仇恨234,567、護盾99,999和多個狀態；檢查數字欄間距、文字裁切及最後一段狀態可捲動到達。
- 呼叫正式流局結算入口，確認修為與巡歷明細出現；每次調整尺寸及直式轉回橫式後，核對原結算節點與完整文字仍保留。
- 結算四人手牌、並列首席長標題、金幣／材料收穫、八段終式明細；捲動後檢查按鈕是否被遮擋、是否超出螢幕與容器邊界。
- 胡牌／大額獎勵案例是顯示fixture，不是自然胡牌或平衡證據。測完還原正式流局狀態，實際點「前往整備」，並核對直式提醒。

- 巡歷介面回歸：208項通過。
- PWA重建、清單核對及24項瀏覽器檢查通過；實際快取版本以同一提交的`pwa-assets.js`為準。
